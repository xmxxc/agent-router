# Linux bundled execution backend

Public Linux dispatch selects this backend with `wfc dispatch --backend bundled --host HOST --task FILE --cwd DIR --report FILE`. The default is tmux. Use the dispatch ID with `wfc status --dispatch ID` and `wfc close ID` in the same state directory. If the dispatcher exits during publication, named status and the list expose the reservation with `createPending=true`. The bundled adapter looks up its original dispatch and attempt. A missing or ambiguous binding keeps cleanup unknown. Close of a recovered execution uses the verified ticket. The hosted assignment's `create.ticket` and `create.identity` identify its original runtime.

Public close records its exact ticket, round and any verified terminal worker outcome before sending. It commits this intent under the same lock that publishes completion messages. Once the intent exists, a worker can retrieve an existing keyed completion with its original body. A first completion or a different key is rejected. If persistence fails before any request can be sent, the caller withdraws the intent under that lock so a fresh close can proceed. A retry of a pending close reads the signed receipt. Named status exposes the backend evidence under `backendObservation`, independently of the workflow scope and the round's completion report. A verified directed cleanup includes `execution_proof` and keeps `cleanup=unknown` and `backendAlive=null`. A missing or mismatched receipt leaves execution cleanup unresolved. A later observation verifies the receipt again. A failure verified at close remains the business result even while the cleanup receipt is unavailable. Status reads the round’s completion messages after observing the backend, so a worker that reported before its exit retains that report. A completed task with unknown backend ownership stays visible in the active list for inspection.

The private protocol supplies the primitives for dispatch (#5) and reconciliation (#18). Each invocation of `wfc --bundled` reads one JSON object on stdin through EOF and prints one JSON result. The launcher, detached guardian, runtime and PTY kernel use the same executable. Set `WFC_STATE` to the owning state directory and `WFC_BUNDLED_CGROUP_ROOT` to a writable cgroup v2 delegation with `cgroup.kill`. The launcher must be allowed to migrate its children into that subtree. Reserve its use for processes trusted to stay within the delegation.

| Operation | Request and result |
| --- | --- |
| `create` | Supply `unit`, `attempt`, absolute `cwd`, string array `argv` and optionally a string map `env` for the worker. Unit and attempt use 1–120 ASCII letters, digits, hyphens or underscores. The guardian drops inherited controller, owner and callback credentials before exec. Supply this attempt’s worker callback explicitly in `env`. On acceptance, save the returned `ticket` verbatim and `identity`. Identity records boot ID, PID and start time for the guardian, service, kernel and worker, plus the cgroup path, device and inode. |
| `lookup` | Supply the current unit and attempt to recover its ticket after losing a launch response. The response includes the phase, creator process identity and observed state, and a Unix millisecond deadline for a pending create. Expiry calls for inspection. Only a verified receipt permits cleanup reconciliation. |
| `inspect`, `read`, `resize` | Supply the ticket. A live read/inspect returns `accepted`, PTY data and `last_input`. Resize also requires `cols` and `rows`. Inspect/read after confirmed cleanup return the terminal proof. |
| `input` | Supply the ticket, UTF-8 `text` and positive integer `seq`. Number inputs from 1 in each generation. Keep the sequence number with the workflow input claim. Only the next number can write. An interrupt uses the same operation with U+0003. Host-specific paste/Enter policy belongs to the caller. |
| `close` | Supply the ticket. `completed` requires the guardian's signed empty-tree receipt. After a lost response the adapter makes a read-only proof check. |
| `cleanup-receipt` | Read-only check against the current ticket. Returns `completed` with `proof.proves = execution-empty`, terminal state and actual identity, or `uncertain` with `cleanup = unknown`. |
| `reconcile` | Apply that proof under the unit lock. On a successful first commit exactly one concurrent caller gets `newly_applied = true`. Repeats return the same proof and `false`. Workflow-level transaction/claim ownership remains with #18. |
| next `create` | Supply a new attempt and the exact `previous` ticket. The adapter checks the applied receipt again. A signed pre-launch rejection permits replacement when its group was never created or its removal was confirmed. An unstarted worker can still have uncertain group cleanup. |

A missing or damaged current index in a unit with history returns `uncertain` and `cleanup=unknown`. Preserve the generation directories. Each new generation saves a signed `index.json` before its predecessor is retired. For recovery under the unit lock, match the generation to the caller’s saved ticket and the predecessor’s signed successor record before restoring that index. An interrupted create with no terminal evidence stays pending. New indexes are signed, and restoring an index from a superseded generation keeps the unit fenced. Reconciliation records the proof in its generation and binds its digest in the signed current index. The signed application marker is the first commit. If mirroring it to the index fails, reconcile returns the proof with `result=uncertain`, `applied=true`, `newly_applied=true` and `recovery_pending=true` to the first caller. Retrying repairs the mirror and returns `newly_applied=false`. Failure before either record commits leaves `applied=false`; an indeterminate commit omits the unknown flags. Either surviving signed record preserves application across repair. Replacement requires both V2 records.

The original unsigned index could be restored from any generation. For units with history, the adapter verifies the retirement records in the other generation directories. They must form a single signed chain ending at the selected generation. A one-way upgrade from a legacy generation can supply this chain. If an older writer introduces a successor without recording the link, the unit remains unknown even after restoration of a genuine signed index. Lookup, reconciliation and replacement require established order. A caller with the exact ticket of a live runtime can still inspect, read or close it. A directed reply has `scope=execution` and `cleanup=unknown`. A confirmed directed close includes the ticket, `execution_cleanup=confirmed` and `execution_proof`. If the authenticated close frame may have been sent and the reply is lost, the adapter checks that ticket’s signed receipt once. A valid receipt confirms execution cleanup while the request result remains `uncertain` and unit cleanup remains `unknown`. A missing or mismatched receipt leaves cleanup unresolved. The adapter sends each close request only once. For a single legacy generation, confirming unit cleanup or replacing the execution requires a matching signed application marker. The unsigned application bit alone cannot establish an earlier commit. Resolving ambiguous history requires independent workflow claim evidence.

The following command creates a unit from a delegated shell.

```sh
printf '%s\n' '{"op":"create","unit":"d-example","attempt":"a-1","argv":["/bin/cat"],"cwd":"/tmp"}' | wfc --bundled
```

The guardian places the runtime in its newly created group before exec. The PTY kernel and worker inherit membership. Between connections the runtime reads the PTY to detect worker exit. On runtime exit the guardian uses the original group descriptor to kill the tree, observes `populated 0`, removes empty subgroups and the owned group, and publishes its HMAC-SHA-256 receipt. If the guardian also dies, missing proof leaves cleanup unknown. Verification requires a terminal state of `closed`, `exited` or `faulted` and an exact match with the independently recorded creation identity. A fault before readiness uses the creation identity recorded by the guardian. If ready promotion was interrupted, the complete signed ready identity in the staging file can verify a faulted receipt. Legacy pre-ready cleanup without a creation binding stays unknown. Only execution emptiness is proved. An outer create/input claim still needs its own delivery outcome.

The private loopback protocol authenticates both endpoints with fresh challenges. Pre-auth frames are bounded to 256 bytes and 0.5 seconds, authenticated requests to 2 MiB and 2 seconds, and a client exchange to 6 seconds. A lost or mismatched reply after sending input returns `uncertain`. The client never retransmits. A pre-send connection or handshake failure returns `definitely-not-sent` for that call. If the current execution already has a verified terminal proof, input and resize return that proof with `result=definitely-not-sent`, `delivery=definitely-not-sent` and `cleanup=confirmed` for this call. If the proof is missing and the recorded service disappeared, changed creation identity or cannot be verified, the response is `result=uncertain`, `delivery=definitely-not-sent`, `cleanup=unknown`, `reconcile=true`. The caller must reconcile that execution before retrying a claim. Retry decisions require the original workflow claim and its stable sequence. Keep the private backend directory beneath trusted, owner-controlled state. Keep capability files out of status and logs.

Run the ordinary tests with `cargo test --workspace --locked`. In a disposable real delegation run the native tree cases with the following command.

```sh
WFC_TEST_DELEGATION=/path/to/delegated/group cargo test --locked --test bundled_linux -- --include-ignored --nocapture
```


In a disposable Linux VM, run `tools/check_bundled_public.sh` as the delegated user with the release `wfc` on PATH and `WFC_BUNDLED_CGROUP_ROOT` set. It needs jq, Perl Digest::SHA, strace with syscall injection, and setsid. The script uses a fresh state directory and simulates interrupted generation history inside that directory. Shut down the disposable VM after the test.
